# `themvora add`

## Prerequisites
- Node.js 22+
- A project that `themvora init` already integrated

Add a theme source to a project `init` already set up.

```bash
themvora add preset mint
themvora add brand apple
themvora add seed "#6366f1" --family indigo
```

## How it works

`init` writes a theme registry and records **the sources it was built from** in a
machine-readable line in that file:

```ts
/**
 * Themvora application configuration.
 *
 * Generated by `themvora init`.
 * …
 * Source: preset mint.
 * themvora:sources: [{"kind":"preset","id":"mint"}]
 */
```

`add` decodes that list, appends its own source, resolves everything through the
same source resolver `init` uses, and regenerates the file with the same
renderer. Nothing is parsed back out of the TypeScript — the alternative would
break the moment a formatter reformatted the file.

That also means `add` is exactly as safe as `init`:

- **Idempotent.** Adding a source the registry already has reports
  `Already present — nothing changed` and writes nothing.
- **Non-destructive.** The file is regenerated only when it carries Themvora's
  generated header. A registry you maintain by hand is never rewritten.
- **Stable defaults.** Adding a source never changes the theme the app opens
  with — the first source's default stays the default.

## Where the themes go

| Project | Registry file |
| ------- | ------------- |
| React, Vue, Svelte, Solid (Vite) | `theme.config.ts` |
| Next.js App Router | `themvora.themes.ts` |

The file is the single declaration the integration reads, so nothing else has to
change. Restart the dev server and the new themes are selectable.

## Working with an existing project

`add` uses `--dir` rather than a positional, because both positionals name the
source:

```bash
themvora add preset iris --dir ./my-app
themvora add brand github --dir ./packages/web
```

## Previewing

```bash
themvora add preset iris --plan
themvora add preset iris --dry-run --json
```

Both print what would change and write nothing.

## When it refuses

`add` stops rather than guessing in three cases, and each says what to do:

- **No registry.** The project has not been integrated — run `themvora init`.
- **A hand-written registry.** The file exists but was not generated by Themvora,
  so `add` will not rewrite it.
- **A registry with no source record.** The file predates the source line. Re-run
  `themvora init` to regenerate it, then add the source again.
