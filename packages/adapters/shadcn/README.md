# @themvora/shadcn

Themvora adapter for shadcn/ui.

Drive shadcn/ui components with Themvora semantic tokens via a CSS-variable adapter that stays in sync at runtime.

- **Package** — `@themvora/shadcn`
- **Library** — shadcn/ui
- **Bridge** — CSS variables
- **Frameworks** — React, Next.js, Remix, Astro, Vue 3, Svelte
- **Documentation** — [themvora-dev.vercel.app/libraries/shadcn](https://themvora-dev.vercel.app/libraries/shadcn)
- **License** — MIT

## How it works

shadcn/ui is not a component package: the CLI copies component source into your project, and those components read CSS custom properties. `@themvora/shadcn` writes the same properties (`--background`, `--foreground`, `--primary`, `--border`, `--ring`, `--radius`) onto the document root from the active theme, so the copied components follow a theme change without being regenerated.

The adapter maps these Themvora roles onto the library's own vocabulary:

| Themvora role | shadcn/ui target |
| --- | --- |
| `background` | `--background` |
| `foreground` | `--foreground` |
| `card` | `--card` |
| `cardForeground` | `--card-foreground` |
| `primary` | `--primary` |
| `primaryForeground` | `--primary-foreground` |
| `secondary` | `--secondary` |
| `muted` | `--muted` |
| `mutedForeground` | `--muted-foreground` |
| `accent` | `--accent` |
| `destructive` | `--destructive` |
| `border` | `--border` |
| `ring` | `--ring` |

## Features

`@themvora/shadcn` ships 6 exports in 2 categories. Each one is documented, with a runnable example, on the [library page](https://themvora-dev.vercel.app/libraries/shadcn/examples).

### Adapter

- **`createShadcnAdapter(options)`** — Installs a tagged `:root` style element
  whose `--*` variables (colors, radius, border, shadow, typography) update as the
  theme changes.
- **`createShadcnVariables(tokens)`** — Deprecated — prefer
  `createShadcnAdapter`. Generates the shadcn CSS-variable map from a token set
  (`theme.tokens`), without touching the DOM. Passing a theme definition yields
  empty values.
- **`useShadcnTheme(runtime, options?)`** — React hook (from
  `@themvora/shadcn/react`) that installs and disposes the adapter onto an
  explicit runtime. Call once in your app root.
- **`injectShadcnCSS()`** — Idempotent, SSR-safe helper that injects the shadcn
  compatibility stylesheet. Called automatically by the hook.

### Options

- **`CreateShadcnAdapterOptions`** — Accepts `strategy` to hand a custom
  token→variable mapping to the adapter.
- **`ShadcnAdapterOptions`** — Typed options for how semantic tokens map to
  shadcn CSS custom properties.

## Installation

Installing this integration is two commands: the library first, then Themvora.
The commands are **framework-specific** — the library's own toolchain differs
between Vite, Next.js, Nuxt, Angular and Astro, and shadcn/ui, daisyUI and
UnoCSS install through a CLI or a build plugin rather than a plain package.
There is therefore no single install line that is correct for every framework;
the exact commands for yours are in its section below.

The documentation page shows them behind package-manager tabs. A README cannot,
so every section repeats the same commands under all four headings. The verbs
each manager uses:

| Package manager | Add a dependency | Add a dev dependency | Run a package |
| --- | --- | --- | --- |
| pnpm | `pnpm add` | `pnpm add -D` | `pnpm dlx` |
| npm | `npm install` | `npm install -D` | `npx` |
| yarn | `yarn add` | `yarn add -D` | `yarn dlx` |
| bun | `bun add` | `bun add -d` | `bunx` |

`@themvora/core` is a normal dependency of `@themvora/shadcn` and of the framework
integration, so it arrives with them. Naming it in the command pins the
runtime version in your own manifest.

### Build configuration and global styles

The library's own stylesheet is imported first, the adapter's variable map
second. That order is what lets the adapter's values win over shadcn/ui's
defaults — reversing it leaves the library looking themed until the first
switch.

**`vite.config.ts`**

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import path from "node:path";
export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: { alias: { "@": path.resolve(__dirname, "./src") } },
});
```

**`tsconfig.json`**

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
```

**`src/index.css`**

```css
@import "tailwindcss";
@import "@themvora/shadcn/shadcn.css";
@import "@themvora/tailwind";

html,
body {
  margin: 0;
  background: var(--theme-color-background);
  color: var(--theme-color-foreground);
}
```

### Attach the adapter

This is where the adapter is registered on the runtime. It writes shadcn/ui's
own CSS custom properties from the active theme, and disposes them on unmount.

**`src/ThemeZone.tsx`**

```tsx
import type { ReactNode } from "react";
import { useThemeRuntime } from "@themvora/react";
import { useShadcnTheme } from "@themvora/shadcn/react";
// Registers the adapter on the runtime from the provider above.
export function ThemeZone({ children }: { children: ReactNode }) {
  useShadcnTheme(useThemeRuntime());
  return <>{children}</>;
}
```

### Theme switching

Mode changes go through Themvora's runtime. The controls below are shadcn/ui's
own components, and they are the only code that changes when the mode does.

**`src/ThemeControls.tsx`**

```tsx
import { useTheme } from "@themvora/react";
import { Button } from "@/components/ui/button";
export function ThemeControls() {
  const { mode, setMode, toggleTheme } = useTheme();
  return (
    <div className="flex items-center gap-2">
      <span className="text-sm text-muted-foreground">Mode: {mode}</span>
      <Button onClick={toggleTheme}>Toggle</Button>
      <Button variant="outline" onClick={() => setMode("light")}>
        Light
      </Button>
      <Button variant="outline" onClick={() => setMode("dark")}>
        Dark
      </Button>
    </div>
  );
}
```

### Theme family

A family is the second axis: the same mode, a different palette. The runtime
carries it beside the mode, so a family picker is one more control and needs no
re-mount.

```tsx
// The same hook carries the family and its setter.
const { family, setFamily } = useTheme();

// One control per family you ship. The literals are checked against your
// theme registry, so a family that does not exist is a compile error.
setFamily("mint"); // "plum" | "mint" | "berry" | "iris" | "citrus" | …
```

The last file composes what the steps above created: the runtime, the adapter

```tsx
import { ThemeControls } from "./ThemeControls";

  return (
    <ThemeZone>
```

### Mount the runtime

Remix owns the document, so this file does more than mount a provider.
`createThemeDocument()` declares the configuration once; the loader resolves the
request's selection from it, and `<theming.Document>` renders the pre-paint
script, the matching `<html>` shell and the runtime provider from that same
configuration. The stylesheet is linked through `links` rather than imported for
side effects.

**`app/root.tsx`**

```tsx
import type { ReactNode } from "react";
import type { LinksFunction } from "@remix-run/node";
import {
  Links,
  Meta,
  Outlet,
  Scripts,
  ScrollRestoration,
  useLoaderData,
} from "@remix-run/react";
import { getBuiltInThemes } from "@themvora/core";
import { createThemeDocument } from "@themvora/remix";
import styles from "./styles.css?url";
export const links: LinksFunction = () => [
  { rel: "stylesheet", href: styles },
];
const themes = getBuiltInThemes();
const theming = createThemeDocument({
  themes,
  defaultTheme: "plum-light",
  mode: "system",
});
// Resolve the selection on the server so hydration matches exactly.
export async function loader({ request }: { request: Request }) {
  return { theme: await theming.resolveInitial(request) };
}
export function Layout({ children }: { children: ReactNode }) {
  const { theme } = useLoaderData<typeof loader>();
  return (
    // Remix owns the document; Document supplies the theme-owned parts: the
    // blocking bootstrap, the matching <html> shell and the runtime provider.
    <theming.Document
      initial={theme}
      htmlProps={{ lang: "en" }}
      head={[
        <meta key="charset" charSet="utf-8" />,
        <Meta key="meta" />,
        <Links key="links" />,
      ]}
      afterContent={
        <>
          <ScrollRestoration />
          <Scripts />
        </>
      }
    >
      {children}
    </theming.Document>
  );
}
export default function App() {
  return <Outlet />;
}
```

### Theme switching

Mode changes go through Themvora's runtime. The controls below are shadcn/ui's
own components, and they are the only code that changes when the mode does.

**`src/components/ThemeControls.tsx`**

```tsx
import { useTheme } from "@themvora/astro/client";
import { Button } from "@/components/ui/button";
export function ThemeControls() {
  const { mode, setMode, toggleTheme } = useTheme();
  return (
    <div className="flex items-center gap-2">
      <span className="text-sm text-muted-foreground">Mode: {mode}</span>
      <Button onClick={toggleTheme}>Toggle</Button>
      <Button variant="outline" onClick={() => setMode("light")}>
        Light
      </Button>
      <Button variant="outline" onClick={() => setMode("dark")}>
        Dark
      </Button>
    </div>
  );
}
```

### Theme family

A family is the second axis: the same mode, a different palette. The runtime
carries it beside the mode, so a family picker is one more control and needs no
re-mount.

```tsx
// The same hook carries the family and its setter.
const { family, setFamily } = useTheme();

// One control per family you ship. The literals are checked against your
// theme registry, so a family that does not exist is a compile error.
setFamily("mint"); // "plum" | "mint" | "berry" | "iris" | "citrus" | …
```

## Troubleshooting

- **The components are themed but the page background is not.** The global
  stylesheet is missing the `html, body` rule from *Build configuration and global
  styles*. Themvora writes `--theme-color-*` on the root element; something has to
  read them.
- **Nothing happens when you switch themes.** The adapter is attached to a
  different runtime than the one the provider created. Call the adapter *inside*
  the provider — that is what the *Attach the adapter* file does — rather than
  beside it.
- **The library's own colours win.** Its stylesheet has to load before the
  adapter's variable map. The import order in the global stylesheet is an
  instruction, not a preference.
- **`shadcn init` stops at "Could not find valid path aliases".** The CLI
  validates the `@/*` alias in `tsconfig.json` before it generates anything, and
  the generated components import through it. The *Build configuration and global
  styles* snippet includes the block for each framework; Svelte needs `$lib`
  instead.
- **The generated components render unstyled.** `@import "@themvora/tailwind";`
  is missing. Without it Tailwind emits no utilities for the component classes the
  CLI wrote.
