# @themvora/cli

The `themvora` command-line toolkit for **Themvora** — generate, validate,
migrate, inspect, and export themes from any shell, for any framework.

It wraps the [@themvora/core](https://www.npmjs.com/package/@themvora/core)
design system into plain shell commands. It reads and writes the same JSON
theme files that every `@themvora/*` framework package consumes.

## Requirements

- **Node.js 18+** (any modern release). No browser package is needed.

## Install

### Global (any directory)

```bash
# npm — `-g` is npm's global-install flag
npm install -g @themvora/cli

# pnpm uses the long `--global` form
pnpm add --global @themvora/cli

# yarn says it differently
yarn global add @themvora/cli
```

After a global install, `themvora` is on your PATH. The packager writes a
small shim for every platform, so it works from Windows cmd, PowerShell,
macOS Terminal, and Linux bash.

### Zero install (npx)

npm, pnpm, yarn, and bun all resolve the same package:

```bash
npx --yes @themvora/cli generate --seed "#6366f1"
```

### One project (best for teams)

```json
{
  "scripts": {
    "theme:generate": "themvora generate --seed \"#6366f1\" --family indigo --output theme.json"
  },
  "dependencies": {
    "@themvora/cli": "^1.3.0"
  }
}
```

```bash
npm run theme:generate
```

## Usage

```
themvora <command> [options]

Commands:
  generate   Generate a theme from a seed, preset, or brand
  list       List brands, presets, styles, and frameworks
  validate   Validate a theme JSON file
  inspect    Inspect a theme's provenance, tokens, and accessibility
  diff       Diff two themes semantically
  explain    Explain how a theme was produced
  audit      Audit a theme or the shipped presets
  doctor     Check a Themvora project's health
  init       Integrate Themvora into a project, or create one
  add        Add a theme source to an existing project
  migrate    Migrate a theme to the latest format
  export     Export a theme to CSS or JSON (--format css|json)
  completion Emit a shell completion script
```

Run `themvora <command> --help` for command-specific options.

> A theme file is either a **pair** (`{ "light": …, "dark": … }`, generated by
> default) or a **single** theme (`{ "name", "meta", "tokens" }`, from
> `--mode light|dark`). Every command accepts either shape.

### Three ways to generate

```bash
# From a seed colour
themvora generate --seed "#6366f1" --family indigo

# From a canonical preset or a brand-inspired recipe
themvora generate --preset mint
themvora generate --brand apple
```

The identifiers come from `@themvora/core`, so they cannot drift from what the
generator accepts. Discover them with `themvora list`:

```bash
themvora list
themvora list presets --json
```

### The full workflow

```bash
themvora list presets
themvora generate --preset mint --output theme.json
themvora validate theme.json
themvora inspect theme.json --accessibility
themvora diff theme.json --preset iris
themvora explain --preset mint
themvora audit presets
themvora doctor
themvora init my-app --framework react
themvora add brand apple
themvora export theme.json --format css --output theme.css
themvora completion bash > /etc/bash_completion.d/themvora
themvora migrate theme.json
```

`diff` compares two themes role by role. Sources are the two positionals — a
theme file, a preset id, or a brand id — or `--preset` / `--brand` / `--seed`
for a side without one:

```bash
themvora diff mint iris
themvora diff theme.json --preset mint
themvora diff --brand apple --brand github
```

`explain` shows how a theme came to be — its recipe, brand anchors, contrast
contract, semantic mapping, and validation:

```bash
themvora explain --preset mint
themvora explain --brand apple
```

`audit` is stricter than `validate`: it gates on the full quality scorecard.
`doctor` checks a project's health.

```bash
themvora audit presets
themvora audit theme.json --strict
themvora doctor
```

`init` creates a project with the framework's official generator, or integrates
into one you already have, then verifies it by running the project's own build
and typecheck:

```bash
# Guided: asks for the project name, package manager, framework and styling
themvora init

# Explicit: no questions at all
themvora init my-app --tool pnpm --framework react
themvora init my-app --tool npm --framework next --preset mint
themvora init my-app --framework react --plan
```

The wizard asks only for what the command line did not supply, in a fixed order:
project name, package manager, framework, Tailwind or plain CSS. `--tool` takes
`npm`, `pnpm`, `yarn` or `bun`, and `--package-manager` is accepted as its
compatibility alias. When neither is given the manager is detected from the
corepack `packageManager` field, then the lockfile, then `npm`; the prompt
preselects whichever manager invoked the CLI.

The prompts need a terminal. `--json`, `--quiet`, `--plan`, `--dry-run`, CI, or
a redirected stdin keep `init` non-interactive, and a missing value is then a
usage error naming the flag that supplies it.

Supported targets are React, Next.js, Vue, Svelte and Solid. Running it twice
changes nothing the second time.

Dependencies are installed **once**, by `init`, after the integration has edited
`package.json` — the framework's generator is invoked with its own
non-interactive flag so it never asks whether to install, and never installs a
second copy. The development server is never started for you; `init` prints the
command that starts it.

The generated app mounts one provider at the framework's documented root, keeps
the showcase UI in its own component, opens in a light theme, and styles itself
entirely from semantic tokens — no second palette. The theme registry lives in
`themes/themes.ts` (or `src/themes/themes.ts`) and is passed to the provider as
props; there is no `theme.config.ts` and no Themvora Vite plugin to register.

`--styling` chooses the styling engine, and plain CSS is the default — the same
default the wizard preselects, so an interactive run and a scripted one agree:

```bash
themvora init my-app --framework react                     # plain CSS
themvora init my-app --framework react --styling tailwind  # Tailwind CSS
```

`css` writes a stylesheet that reads `var(--theme-color-*)` and adds no
dependency. `tailwind` writes a Tailwind CSS v4 entry point that imports
`@themvora/tailwind`, whose `@theme` mapping turns the same tokens into
utilities such as `bg-background` and `bg-card`, and records `tailwindcss` plus
the framework's plugin as dev dependencies before the single install runs.
Either way, switching themes repaints the whole starter, and either way the
starter is the same application — the choice changes how it is styled, not what
it does. `--styling` does nothing to an existing project: its stylesheet is
yours, and `init` says so rather than replacing it.

In a project `init` scaffolded, the scaffold's unused demo files — its own
stylesheet with a second palette, its demo component, its logo assets — are
removed, because nothing in the starter refers to them. In an existing project
nothing is removed and your files are left alone.

`add` extends a project's theme registry afterwards. It reads the sources the
registry records, so it is idempotent and never rewrites a hand-written config:

```bash
themvora add preset iris
themvora add brand github --dir ./my-app
themvora add seed "#6366f1" --family indigo
```

`migrate` reports by default and only writes when told to:

```bash
themvora migrate theme.json              # migrated theme to stdout
themvora migrate theme.json --dry-run    # what would change, writes nothing
themvora migrate theme.json --write      # migrate in place
```

`completion` prints a script for bash, zsh, fish or Powershell. Registry values
are resolved from the installed CLI, so they cannot go stale.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Runtime or command error |
| `2` | Invalid arguments / usage error |
| `3` | Validation failed (`validate`) |

## Editor integration

The same theme files can be explored, previewed and validated inside VS Code
with **[Themvora Theme Studio for VS Code](https://marketplace.visualstudio.com/items?itemName=themvora.themvora-for-vscode)** — a
companion extension that reads `defineTheme()` definitions and theme JSON
statically, previews a theme across a dashboard and component gallery, and
reports contrast failures per token. It is published on the Visual Studio
Marketplace as `themvora.themvora-for-vscode`; it is an editor extension, not an
npm package.

Install it from the Extensions view (`Ctrl+Shift+X`) by searching for
**Themvora Theme Studio**, or run
`code --install-extension themvora.themvora-for-vscode`.

It does not replace the CLI: `init`, `add`, `doctor` and `export` remain
terminal commands.
